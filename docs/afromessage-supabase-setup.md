# AfroMessage + Supabase Auth setup

Serkle uses a Supabase **Send SMS Hook**. Supabase creates, expires and verifies
the OTP. The `send-sms` Edge Function verifies the signed hook request and sends
that exact code through AfroMessage's normal `/api/send` endpoint.

Do not use AfroMessage's `/api/challenge` endpoint for this flow because it
creates a second provider-owned code that Supabase cannot verify.

## Files to deploy

- `supabase/functions/send-sms/index.ts`
- `supabase/functions/_shared/afroMessage.ts`
- `supabase/config.toml`

No database migration or service-role key is required.

## 1. Configure server-only secrets

Create a new API token in AfroMessage and store it directly in Supabase. Never
put provider credentials in Vercel, a `VITE_*` variable, Git, logs or chat.

```powershell
supabase secrets set AFROMESSAGE_API_TOKEN="YOUR_NEW_API_TOKEN"
supabase secrets set AFROMESSAGE_SENDER_NAME="Serkle"
supabase secrets set AFROMESSAGE_IDENTIFIER_ID="YOUR_IDENTIFIER_UUID"
```

The sender name must be approved by AfroMessage before production use. Their
default sender can be used only for provider-approved beta testing.

## 2. Deploy the Edge Function

```powershell
supabase functions deploy send-sms --no-verify-jwt
```

Function URL:

`https://fkeyentcklsuqecqgmak.supabase.co/functions/v1/send-sms`

JWT verification is disabled because the user does not have a JWT during
signup. The function instead verifies Supabase Auth's Standard Webhooks
signature before contacting AfroMessage.

## 3. Register the Supabase Auth hook

In Supabase Dashboard:

1. Open **Authentication → Hooks**.
2. Add or enable **Send SMS Hook**.
3. Select **HTTP** and enter the function URL above.
4. Store the generated hook secret as an Edge Function secret:

```powershell
supabase secrets set SEND_SMS_HOOK_SECRET="v1,whsec_YOUR_GENERATED_HOOK_SECRET"
```

## 4. Enable and test phone authentication

In **Authentication → Sign In / Providers → Phone**, enable phone signups and
phone confirmations. Serkle sends E.164 numbers and verifies the submitted code
through `supabase.auth.verifyOtp`.

Test both Ethiopian mobile prefixes:

- Ethio Telecom: `+2519…`
- Safaricom Ethiopia: `+2517…`

## Production safeguards

- Keep the resend cooldown at 60 seconds or longer.
- Enable CAPTCHA and review Supabase Auth SMS rate limits.
- Use Supabase test phone numbers for automated tests to avoid paid messages.
- Monitor Edge Function logs and AfroMessage message reports.
- Never log OTP values, complete phone numbers or provider response bodies.
- Treat AfroMessage acceptance as queued, not final handset delivery.

## Verification checklist

- A new phone signup receives exactly the OTP generated by Supabase.
- A valid code verifies successfully in Serkle.
- Wrong and expired codes are rejected by Supabase.
- Resend sends only one new request after the cooldown.
- Invalid hook signatures return `401` without contacting AfroMessage.
- Missing provider configuration fails without exposing credentials or OTPs.
